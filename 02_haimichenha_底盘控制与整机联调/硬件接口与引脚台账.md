# 硬件接口与引脚台账

> 本台账用于双臂小车的固件与接线复核。它记录仓库现有双臂控制入口的接口事实；不同 `main_*.c` 之间存在复用冲突，不能同时初始化。

## 1. 信息来源与优先级

1. [PCB 原理图展示](hardware/小车pcb原理图展示.pdf)：硬件连线和板级设计归档。
2. [firmware/Src/main_bluetooth_car_arm.c](firmware/Src/main_bluetooth_car_arm.c)：双臂小车蓝牙控制/总线舵机联调入口，文件头描述当前测试串口配置。
3. `firmware/Hardware/` 中对应驱动：电机、总线舵机、蓝牙和 Nano UART 模块。
4. 实物接线和上电前测量：用于最终确认，优先级高于旧照片或口头记录。

## 2. 双臂控制入口已声明的串口配置

| 功能 | MCU 接口 | 入口文件中的用途 |
| --- | --- | --- |
| 蓝牙控制 | USART3 全重映射，PD8=TX、PD9=RX，9600 8N1 | 手机/蓝牙驾驶命令。 |
| 总线舵机 | UART4，PC10=TX、PC11=RX，115200 8N1 | 双臂动作组和舵机控制器通信。 |
| 调试/陀螺仪 | 由入口和 BSP 初始化决定 | 仅在相应测试模式启用。 |
| Nano 串口联调 | 见 `firmware/Hardware/app_nano_uart_test.c` 与 `../03_邓炜_Nano视觉识别/yolov5/nano_uart_link_test.py` | PING、ECHO、VISION 等联调报文。 |

## 3. 四轮驱动：物理接线快照与代码边界

下表是[电机接线已知记录](firmware/logs/motor_wiring_known_good_20260712.md)
中的架空方向检查快照；其记录的前轮为 TB6612、后轮为 L298N 两路扩展。
这是开环极性验证，不是闭环性能结论。

| 位置 / 驱动 | PWM / 使能 | 正向对应的方向电平 | 记录状态 |
| --- | --- | --- | --- |
| 左前 LF / TB6612 | PA2 / TIM2_CH3，PE6=STBY | PE2=0，PE3=1 | 日志记录的物理方向检查 |
| 右前 RF / TB6612 | PA3 / TIM2_CH4，PE6=STBY | PE4=1，PE5=0 | 日志记录的物理方向检查 |
| 左后 LR / L298N | PA6 / TIM3_CH1（ENA） | PC6=1，PG1=0 | 日志记录的物理方向检查 |
| 右后 RR / L298N | PA7 / TIM3_CH2（ENB） | PE9=0，PE7=1 | 日志记录的物理方向检查 |

- 该记录还明确 `PE8` 未用于后轮控制，因为它未通过当时的 ODR/IDR 与运动测试。
- [firmware/Hardware/bsp_l298n.c](firmware/Hardware/bsp_l298n.c) 另含一套四路
  L298N 风格映射（前轮 PA0/PA1、后轮 PA6/PA7）。它与上表的“前 TB6612、后
  L298N”实物快照不是同一配置；编译前必须以选定 `main`、实际 PCB 和接线为准，
  不得混用。
- [四轮方向检查记录](firmware/logs/motor_wiring_known_good_20260712.md) 的顺序为
  LF、RF、LR、RR，每个极性均单轮、架空、定时观察；它只证明该次接线下的方向响应。

## 4. 复用冲突与启用前检查

- PC10/PC11 在双臂控制入口中分配给总线舵机 UART4；如果另一个测试程序把它们分配给雷达或其他模块，必须切换入口并重新核验接线。
- PD8/PD9 在该入口中用于蓝牙 USART3 全重映射；不得同时声明为其他串口或 GPIO 功能。
- 电机、舵机、视觉联调代码存在多个测试入口。每次编译前只选一个 `main_*.c`，并确认工程配置实际包含该文件。
- 本文不把 PWM 寄存器值等同于电机扭矩、实际方向或闭环质量；需通过架空轮测试、串口日志和实车验证确认。

## 5. 上电前最小检查表

1. 断电测量主电源地到 STM32、L298N/TB6612、舵机电源和蓝牙地的连续性；确认 PCB
   主地线未断后再接电。
2. 电机与舵机电源、逻辑地和急停/安全状态正常；舵机使用规定的外部电源，不从 MCU
   3.3 V 电源轨取电。
3. 选定 `main` 的 UART、波特率、TX/RX 交叉连接与外设一致。
4. 先架空单独验证电机方向和动作组，再进行整车联调。
5. Nano 串口联调先使用 `nano_uart_link_test.py` 的 PING/ECHO，再连接视觉业务数据。

> [用户确认] 本项目曾在整车上电时出现单片机异常发热，后排查为 PCB 主地线断开并
> 导致 ZET6 损坏。该项是故障复盘信息，不等同于已经完成修复；每次重新上电前均应执行
> 上述连续性检查并保留测量记录。
