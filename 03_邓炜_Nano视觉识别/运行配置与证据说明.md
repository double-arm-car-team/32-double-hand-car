# Nano 视觉运行配置与证据说明

> 本文固定本项目在仓库中采用的视觉运行口径；它只描述已确认的代码配置，不以截图或引擎文件名替代性能验收。

## 1. 已确认的运行链路

| 项目 | 结论 | 仓库依据 |
| --- | --- | --- |
| 检测框架 | YOLOv5 | `yolov5/` 检测与训练工程。 |
| 推理精度 | **FP32** | `detect_ultra.py` 加载 `yolov5n_fp32_320.engine`；输入数组和输出缓冲区使用 `numpy.float32`。 |
| 输入尺寸 | 320×320 | `detect_ultra.py` 的 `letterbox(..., (320, 320))`。 |
| 检测输出 | 检测框、类别编号、置信度和滚动 FPS 显示 | `detect_ultra.py` 的显示与 NMS 流程。 |

运行时从 `yolov5/` 目录执行：

```bash
python3 detect_ultra.py 0
```

`0` 表示默认摄像头；也可替换为图片路径进行单图验证。设备上的 CUDA、TensorRT、摄像头权限和显示环境须按实际 Nano/Jetson 环境配置。

## 2. 训练部署、运行优化与最终配置的区分

视觉工作按先后分为两个不应混淆的阶段：

1. **邓炜：YOLOv5 视觉训练与部署。** 该阶段产出模型、检测工程与视觉运行链路；不将其表述为 haimichenha 独立完成。
2. **haimichenha：部署完成后的 SSH 运行时优化。** 该阶段连接 Nano 检查并调整视觉运行配置、采集性能诊断；不将其表述为邓炜的模型训练或初始部署。

仓库保留了不止一个引擎与检测脚本，目的是保存开发过程。`detect_fast.py`、`yolov5n_fp16*.engine` 和 [SSH 优化试验归档](evidence/haimichenha_ssh_optimization_20260713/README.md) 属于第二阶段的对比/诊断材料；它们不定义本项目最终运行配置。项目报告、答辩和 README 统一以本页的 **YOLOv5 + TensorRT FP32 + 320×320** 为准。

其中，`vision_live_320_fp16.log` 是 haimichenha 在 SSH 优化阶段留存的原始运行日志：其对应 320×320、fixed 后处理和 `FP32+FP16` TensorRT 试验配置，428 个滚动统计点的 `fps_avg` 均值为 32.526 FPS。它可作为“完成过该次优化试验”的可核验记录；但它**不能**被写成最终 FP32 链路达到 32.526 FPS，也不能被归为邓炜的训练/部署结果。

## 3. 性能结论的证据要求

当前 `evidence/` 中的两张图只能证明检测界面和整机视觉画面曾经输出；界面上的瞬时 FPS 不等于稳定帧率。若补充 FPS、延迟或识别精度，至少应同时提交：

1. 实际命令、脚本提交版本、`yolov5n_fp32_320.engine` 的文件校验值和输入尺寸；
2. 原始终端日志或 CSV，以及统计脚本；
3. 摄像头分辨率、场景、运行时长和是否包含显示等待；
4. 若比较优化效果，提供相同条件下的基线记录。

未满足这些条件时，报告仅表述为“完成 YOLOv5 FP32 检测与显示链路验证”，不外推为识别精度、平均 FPS 或闭环控制能力。
